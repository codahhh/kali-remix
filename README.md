# KALI WEB OS

A browser-based, offline-first Linux/XFCE-inspired desktop **simulation** — dark navy canvas, Kali-blue
accents, draggable windows, a fake-but-useful terminal, a real virtual filesystem and a defensive
cybersecurity learning lab.

> **This is not Kali Linux.**
> It is a static React app that *looks and behaves like* a small Linux desktop. It cannot install
> packages, run real binaries, scan networks, read your real files, processes, disks or hardware, or
> "hack" anything. It is not affiliated with Offensive Security or the Kali Linux project. Every
> terminal command is interpreted by a small allow-listed JavaScript interpreter, and every
> network/system metric is either browser-provided or explicitly labelled as simulated.

## What it does

**Desktop shell**

- Deep navy → black gradient background with six authored wallpapers (onyx, abyss, grid, aurora,
  carbon, steel), animated aurora glows and a Kali-blue accent system (seven accent palettes).
- Top panel with logo, window list, live clock/date, online state, install button and status tray.
- Application launcher with search, categories and keyboard navigation; dock with pinned apps and
  running indicators; desktop icons for quick actions.
- Windows that can be dragged, resized (eight edge/corner handles, pointer devices only), minimised, maximised, restored,
  focused and stacked by z-order. `Alt+Tab` / `Alt+Shift+Tab` cycle windows, `Alt+T` opens the
  terminal, `Alt+W` minimises everything, `Escape` closes menus and dialogs, and the previously
  focused element is restored after a dialog closes.
- Boot splash, window open/close/minimise animations, hover/press feedback, and a "reduce motion"
  friendly CSS layer.

**Mobile & tablet**

- Below 1024 px the desktop is replaced with a home screen of app tiles plus a bottom taskbar
  (Home / Apps / Windows / Settings). Windows go full-screen with a touch-sized titlebar.
- A window switcher sheet lists open windows; the launcher becomes a full-width sheet.
- `viewport-fit=cover` plus `--safe-*` variables keep the panel and taskbar clear of notches and
  home indicators. Terminal input uses a normal `<input>` so mobile keyboards behave.

**Apps**

| App | Real | Simulated |
| --- | --- | --- |
| **Terminal** | Virtual filesystem in IndexedDB, command history, tab completion, `man` pages | Everything else — output is generated by an allow-listed interpreter |
| **Files** | Create / rename / duplicate / move / delete real virtual files, breadcrumbs, grid & list views, sorting, "open terminal here" | Nothing |
| **Text Editor** | Reads/writes the virtual FS, unsaved-change guard, word count, line numbers | Nothing |
| **Cyber Lab** | Lesson progress saved locally; immediate answer feedback; exercises graded | The fictional log lines, file permissions and hosts |
| **Network** | Browser-provided network hints (connection type, effective speed, RTT, online state, user agent hints) | The whole topology, traffic animation and IP addresses (documentation ranges) |
| **System Monitor** | Storage estimate/quota, filesystem node counts, service-worker state, session uptime, window/app state | CPU, memory, process list and sparkline history |
| **Settings** | Language, theme, wallpaper, accent, terminal font size, sound, export/import, reset | Nothing |

Every simulated value is labelled in the UI (`Simulated`, `Browser-provided`, `Example topology`) —
there are no fake "real" claims.

## App honesty matrix

| Claim | Reality |
| --- | --- |
| "Kali Linux" | A visual homage. No Kali packages, tools, kernel or shell are present. |
| "Shell" | `execute()` over a fixed command table. No `eval`, `Function`, `child_process`, WebSocket or `fetch`. |
| "Filesystem" | A JSON tree persisted in IndexedDB (seeded with sample notes, logs and a lessons folder). |
| "Network" | `navigator.connection`, `navigator.onLine` and `navigator.userAgent` only; the topology is decorative. |
| "System monitor" | `navigator.storage.estimate()`, `performance.memory` (Chromium only) and app state. CPU/RAM charts are generated locally. |
| "Cyber lab" | Reading, quizzes and log triage on fictional data. No targets, exploits, payloads or scanning. |

## Terminal command reference

Thirteen allow-listed commands, with argument validation, `--help`-ish usage errors and realistic
error messages (`bash: foo: command not found`, `cd: /nope: No such file or directory`).

```
help  clear  pwd  ls  cd  mkdir  touch  cat  echo  whoami  hostname  uname  date  history  tree  man
```

- Single/double quotes and backslash escapes are supported; there is **no** globbing, expansion,
  substitution, pipes, redirection, `&&`, or `;` chaining. `help <cmd>` and `man <cmd>` document each
  command, and bare `help` lists the allow-list.
- Prompt: `kali@kali-sim:~$`, home `/home/kali`, host `kali-sim`, kernel string ends in
  `KALI-WEB-OS (simulation)`.
- History persists in the window session; `ArrowUp`/`ArrowDown` walk it, `Tab` completes commands and
  paths, `Ctrl+L` clears, `Ctrl+C` abandons the current line.
- Input is capped (`MAX_INPUT_LENGTH`) and treated as untrusted text; output is rendered as React
  text nodes, never as HTML.
- Success is silent for `mkdir`, `mv`, `cp`, `rm`-style operations, matching real shell behaviour.

## Quick start

Requirements: Node.js 20+ and npm.

```bash
npm install
npm run dev          # http://localhost:5173 (also bound to 0.0.0.0)
npm run build        # type-check + production build into dist/
npm run preview      # serve dist/ on http://localhost:4173
npm run typecheck    # strict TypeScript, no emit
npm test             # 61 logic/security assertions + 55 jsdom UI assertions
```

`npm run icons` regenerates every PWA icon from `public/icons/icon.svg` with `sharp`.

Production output is a static bundle — host `dist/` on any static server (HTTPS is required for the
service worker and installation outside `localhost`). No backend, no accounts, no paid APIs.

## Install as a PWA

The service worker is registered **only in production builds** (`vite build` + `vite preview` or a
deployed `dist/`). Installation needs a secure context.

| Platform | Steps |
| --- | --- |
| **Android** (Chrome, Edge, Samsung Internet) | Browser menu → *Install app* / *Add to Home screen*, or the install icon in the address bar. |
| **iOS / iPadOS** (Safari) | Share → *Add to Home Screen* → *Add*. Opens full-screen. |
| **Desktop** (Chrome, Edge, Brave) | Install icon in the address bar or menu → *Install KALI WEB OS…*. |

Once installed it launches standalone (no browser chrome), keeps the app shell in the cache, and works
offline: the desktop, your files and your preferences all load without a network. The service worker
uses network-first for navigations and stale-while-revalidate for hashed assets, and deletes old cache
versions on activation.

**iOS caveat:** there is no `beforeinstallprompt`, installation is manual, background sync is
unavailable, and iOS may evict site storage under pressure. Use **Settings → Data → Export** to save a
JSON backup. The app never promises features Safari does not have.

In-app install instructions (`How to install`) mirror the table above and are translated FR/EN.

## Architecture

```
src/
  main.tsx                 mounts providers + App, applies theme, registers the SW in production
  App.tsx                  shell composition: wallpaper, panel, icons, dock, windows, launcher, nav
  index.css                design tokens (RGB channel triplets), wallpapers, animations, a11y layers
  lib/
    types.ts               shared domain types (FS nodes, prefs, windows, app ids)
    paths.ts               POSIX path helpers, validation, `~` tildification
    idb.ts                 tiny promise wrapper over IndexedDB (no dependencies)
    seed.ts                initial virtual filesystem
    fs.ts                  pure tree operations + import/export validation
    prefs.ts               preference defaults, persistence, theme application
    i18n.ts                typed EN/FR dictionary (~500 keys) + interpolator
    sound.ts               WebAudio-generated UI sounds (no audio files)
    localized.ts           locale-aware helpers
  state/
    PreferencesContext.tsx language, theme, wallpaper, accent, font size, sound, session persistence
    FsContext.tsx          loads the tree from IndexedDB, exposes mutations, recomputes stats
    WindowContext.tsx      open/focus/minimise/maximise/resize/close, z-order, layout per breakpoint
    ToastContext.tsx       transient feedback queue
    PwaContext.tsx         install prompt, standalone detection, service-worker state
  hooks/                   useViewport, useNow, usePwa, useOnline
  components/              Panel, Dock, Launcher, DesktopIcons, WindowFrame, WindowLayer,
                           MobileNav, MobileSwitcher, BootSplash, InstallDialog, AboutDialog, ui/*
  apps/
    meta.ts                app metadata: titles, icons, default/min sizes, categories
    registry.tsx           appId → lazily rendered component
    terminal/              interpreter.ts, man.ts, TerminalApp.tsx
    files/                 FilesApp.tsx, MoveDialog.tsx, fileIcons.tsx
    editor/                EditorApp.tsx
    lab/                   lessons.ts, Exercises.tsx, useLabProgress.ts, CyberLabApp.tsx
    network/               NetworkApp.tsx
    monitor/               MonitorApp.tsx
    settings/              SettingsApp.tsx
```

**Design principles**

- One context per concern; no global mutable stores, no state library.
- Apps receive `{ windowId, initialProps }` and are mounted inside a single `WindowFrame`; cross-app
  handoffs go through `openApp('editor', { props: { path } })` or `openApp('terminal', { props: { command, cwd } })`.
- Pure logic (`fs.ts`, `paths.ts`, `interpreter.ts`, `lessons.ts`) is framework-free and unit-tested in
  Node without a DOM.
- Tailwind colour tokens are CSS variables in **channel-triplet form** (`--win-rgb: 12 18 32`) so that
  opacity modifiers (`bg-surface-win/55`) compile to valid `rgb(var(--win-rgb) / .55)` rules in both
  themes. Alpha-carrying surfaces use `calc(var(--soft-alpha) * …)` so glass panels stay subtle.
- Strict TypeScript (`strict`, `noUnusedLocals`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`)
  with `tsc -b` in the build. No `any` in app code.

## Data model & persistence

| Storage | Key / database | Contents |
| --- | --- | --- |
| IndexedDB | `kali-web-os` → `fs` | Virtual filesystem tree (files, folders, timestamps) |
| localStorage | `kaliwebos.prefs.v1` | Language, theme, wallpaper, accent, terminal font size, sound |
| localStorage | `kaliwebos.session.v1` | Open windows and layout (restored on reload when the viewport allows) |
| localStorage | `kaliwebos.lab.v1` | Cyber Lab lesson/exercise progress |

Limits enforced everywhere: 96 KiB per file, 2 MB per import, 1.5 MB total, 800 nodes, depth 24.
Imports are size-checked, JSON-parsed, shape-validated and previewed in a confirmation dialog before
replacing anything; the same goes for **Reset workspace**. If IndexedDB is unavailable (private mode,
blocked storage) the app keeps working in memory and tells you so.

## Security model

- **No dynamic code execution:** no `eval`, `new Function`, `setTimeout(string)`, `child_process`, or
  host command APIs. Terminal input is tokenised and dispatched to `Object.hasOwn(handlers, name)`.
- **No HTML injection:** no `dangerouslySetInnerHTML`, no `innerHTML` assignment, no `document.write`.
  All user text is rendered through React text nodes.
- **No network activity from the app:** no `fetch`, `XMLHttpRequest`, `WebSocket` or external URLs in
  `src/`. The only network requests are the app's own static assets.
- **Untrusted input:** file names and paths are validated (`validateName`, `assertCreatableName`),
  imports are validated and capped, terminal input length is capped.
- **No tracking, analytics or third-party scripts.** No cookies. Everything runs client-side.
- Static assertions in `scripts/logic-tests.mjs` fail the test suite if any of the above regresses.
- The service worker only caches same-origin `GET` requests.

## Accessibility & responsiveness

- Semantic landmarks (`header`/`nav`/`main`), `role="dialog"` + `aria-modal` for dialogs and window
  frames, labelled icon buttons, `aria-current` on active nav items, live regions for toasts and
  terminal announcements.
- Full keyboard operation: `Tab`/`Shift+Tab` with visible `focus-ring`, `Escape` to dismiss, arrow keys
  in menus and history, `Enter` to launch, labelled inputs for dialogs.
- Respects `prefers-reduced-motion` (animations collapse) and follows `prefers-color-scheme` on the
  very first visit, before you pick a theme in Settings.
- Breakpoints: phone (< 640), tablet (640–1023, full-screen windows + bottom nav), desktop (≥ 1024,
  floating windows + dock). Tested at 390×844 and 1440×900.

## Testing

Two headless suites, no browser download required:

```bash
npm run test:logic   # pure logic + PWA assets + static security scans (61 assertions)
npm run test:ui      # jsdom render of the real <App> with all providers (55 assertions)
npm test             # both
```

`test:logic` covers path handling, filesystem operations, import/export validation, tokenisation,
every terminal command's success and error paths, completion, `man` pages, manifest/icon assets (PNGs
verified by IHDR) and forbidden-API scans.

`test:ui` mounts the actual application with real providers, then drives it: desktop shell renders,
launcher opens/searches/closes, terminal runs `help`/`pwd`/`ls`/`cat`/`mkdir`, files create a folder via
the dialog, editor saves, Cyber Lab answers a question, network and monitor render their labelled
sections, settings switch to French and back, the light theme re-tunes the accent for contrast, wallpaper
changes apply, reset is cancelled safely, a window closes, and the mobile layout at 390×844 exposes the
four-item taskbar plus the window switcher.

## Known limitations

- **Not Kali Linux.** No real binaries, packages, kernel or networking. Nothing here can touch your host.
- **No real hardware metrics.** CPU/RAM/process data is generated for the demo and marked as simulated;
  only storage estimates and browser state are real.
- **No network scanning or probing** — by design and by browser sandbox rules. The topology and IPs
  (10.0.42.0/24, 203.0.113.24) are fictional documentation ranges.
- **Single-user, single-device.** Data lives in this browser profile; there is no sync. Clearing site
  data deletes your virtual files.
- **iOS PWA gaps:** manual install, no `beforeinstallprompt`, possible storage eviction, no background
  sync. The UI states this instead of pretending otherwise.
- **Service worker is production-only**, so `npm run dev` will not install/offline-cache. Use
  `npm run build && npm run preview`.
- Window positions are not draggable on touch devices (full-screen stack instead); resize handles are
  desktop-only by design.
- The JS bundle is a single ~555 kB chunk (~164 kB gzipped); code-splitting per app was skipped to keep
  the offline cache and lazy-mount logic simple.
